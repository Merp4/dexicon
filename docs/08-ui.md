# 08 — UI

## Intent

Minimal but professional. The UI exists to answer four questions and to do nothing else:

1. What is indexed, and is it current?
2. What is the indexer doing right now, and did anything fail?
3. Does search actually return what I expect?
4. Who can see what?

Anything that does not serve one of those is not in v1.

## Stack

React 19 + Vite + Tailwind v4, built at image build time into `wwwroot` and served by the
same ASP.NET Core host. Dark and light, following `prefers-color-scheme` with a manual
override.

**Components are shadcn** (Radix primitives + `cva` + `cn`), living in
`src/components/ui` exactly as the shadcn CLI writes them, so `shadcn add` and
`shadcn diff` keep working. `src/ui.tsx` is the layer between that and Dexicon's own
vocabulary — `Modal`, `Field`, a `Badge` with a tone, a `Chip` for "one of these is
current", a `Button` whose confirming variant is called `primary`.

This replaced hand-rolled primitives, for one reason. `.input` and `.btn-primary` were
opt-in classes on bare elements, and a whole modal shipped with every field rendering
with no border and every primary button identical to Cancel. Nothing threw, the types
were fine, the build was clean and 163 server tests passed; it was found by someone
looking at a screenshot. A component you cannot construct *without* its styling removes
the whole class of mistake.

The palette is not duplicated. `index.css` maps shadcn's token names onto the oklch
tokens already defined, through `@theme inline`, so a generated component arrives
Dexicon-coloured in both modes. Note that shadcn's `accent` means "hover surface" while
Dexicon's `--accent` is the brand blue: the blue is `primary` here, and nothing redefines
`--accent`.

Icons are `lucide-react`, on the navigation and on actions that are easy to confuse or
expensive to get wrong. Not on everything.

**The API client is generated** from the OpenAPI document by `@hey-api/openapi-ts`, from
the `Dexicon.json` that `dotnet build` writes — a file, not a running instance, so the
client always matches the code it came from. `src/api.ts` is a thin facade over it.

Two things that facade must keep doing, both learned the hard way:

- **Attach the token itself.** The client's `auth` option is only consulted for
  operations the OpenAPI document marks as secured. The document declared no security
  scheme, so `auth` was never called, every request went out anonymous, and the UI
  reported the resulting 401 as a bad token. The document now declares the scheme *and*
  a request interceptor sets the header, because whether a request carries credentials
  should not depend on a generated file being right.
- **Read the response envelope.** `throwOnError: true` was configured and silently did
  not apply — the generated SDK still defaults to `ThrowOnError = false`, so a failure
  returns `{ data: undefined }`. Returning that `undefined` put it into component state
  and the next `.map` blanked the page. `call()` checks `error` and `response.ok` rather
  than trusting the flag.

## Tests

`vitest` + jsdom + Testing Library, `npm test`. They assert `data-slot` and `data-variant`
— the component library's own markers — rather than class lists, because "this is the
component, wearing the variant asked for" is the thing that broke and a class list is free
to change. jsdom computes no layout, so nothing here can tell you a field is *visible*;
that needs a real browser and is a slower, different kind of test.

```
│ Access     │                                                         │
│ Settings   │                                                         │
└────────────┴─────────────────────────────────────────────────────────┘
```

The tenant switcher is in the header, always visible, and every view is scoped to it. The
two status dots are live (SSE) and open a popover with the actual detail — Qdrant version
and collection count; Ollama model, whether it is resident, and last embedding latency.
A dev tool that hides whether its dependencies are healthy wastes an hour of someone's day
per incident.

## Views

### Search

The default landing view, because it is the thing you want to check.

- Query box; corpus multi-select (defaults to all visible); mode toggle
  `Hybrid | Semantic | Keyword`; limit.
- Results as cards: `file_path:start-end` as a monospace heading, `section` and language as
  subtext, the chunk content in a syntax-highlighted block, corpus badge, score.
- Each result has **copy path**, **copy chunk**, and **show context** (expands to the
  neighbouring indexed lines via `get_context`).
- A collapsible **explain** panel per search: which corpora were resolved, how many
  candidates each retriever returned, fusion used, total time. This is how you tell "the
  index is bad" from "the scope was wrong", and it is the single most useful thing the UI
  can show.
- Degraded searches render a banner naming the reason — never a silently keyword-only
  result that looks like a hybrid one.

### Corpora

List: name, sources, files, chunks, embedding model, last indexed, visibility badge, state.

Detail:

- **Sources** — add a workspace path (a picker that browses the mounted `/workspaces` tree,
  so you cannot type a path that does not exist) or an upload drop zone. Per-source
  `.gitignore` toggle, include/exclude globs, size cap.
- **Files** — paginated, filterable by status. `skipped` and `failed` rows show
  `status_detail` inline. This is where "why isn't my PDF searchable" gets answered:
  *no text layer — scanned PDF, OCR not supported*.
- **Chunk sets** — every way this corpus is cut, each with its model, dimensionality,
  size and overlap, strategy flags, chunk count and pending count. The default is badged;
  each row shows the `corpus:set` name it answers to, with a copy button.

  **Add set** opens an editor that inherits from the default, so "the same but finer" is
  two fields. **Promote** is disabled while a set still has pending files, with the count
  in its tooltip — disabled rather than hidden, because the reason is the point, and a
  button that vanishes teaches nothing. Promoting a half-built set is the outage that
  building it separately exists to prevent.

  A set's model is fixed once it exists, and the editor says so: a different model is a
  different vector space, so it is a new set and a promotion, not an edit.
- **Visibility** — private / shared with everyone / shared with specific tenants.
- **Actions** — Refresh, Full reindex, Delete. Delete requires typing the corpus name; it
  destroys an index that may have taken an hour to build.

Creating a corpus is one dialog: name, embedding model (with the trade-off table from
[04](04-ingestion.md) inline), first source. Everything else has a working default, and
the corpus is born with one chunk set named `default` carrying it.

### Jobs

Current job with a progress bar, phase, current file, counts (`done / skipped / failed`),
and a derived time estimate. History below, newest first, each expandable to its per-file
failures.

`degraded` is a first-class state with its own colour, distinct from both running and
failed, showing the backoff count and next retry. A job that is technically running but
achieving nothing must not look like a job that is working.

### Access

List, create, disable. Per tenant: its corpora, its tokens.

Token creation shows the secret **once**, in a dialog with a copy button and a plain
warning that it will not be shown again, alongside a ready-to-paste command:

```bash
claude mcp add --transport http dexicon http://localhost:8477/mcp \
  --header "Authorization: Bearer dex_..." \
  --header "X-Dexicon-Tenant: my-project"
```

That snippet is the highest-value thing on the page — it is the step between "installed"
and "working".

Token list: name, scopes, created, last used, expiry, revoke. Never the secret.

### Models

What this Dexicon's Ollama has actually pulled, because choosing a model should be a list
and not a typing exercise — a typo previously surfaced as a 503 at corpus creation with no
hint of what the legal values were.

Providers run along the top when more than one is configured. One that is configured but
missing its credential is marked, with the reason — otherwise it looks identical to a
working one until someone picks it and an index fails an hour later.

Each row: name, size, dimensionality where known, and whether a chunk set uses it.

**Test limits** measures what the model actually accepts — dimensions, the real input
limit, and whether it truncates silently — and suggests a chunk size with headroom. It
embeds throwaway filler and indexes nothing. This is how you find out that a model quietly
drops the end of an over-long chunk, which is otherwise undetectable: a truncating model
returns a perfectly good vector for the part it read.

**Pull** takes a model name and streams progress, because a pull is gigabytes and minutes
and a bar that only moves when it finishes is not a progress bar. It appears only for
providers whose models are local; you cannot pull a model into OpenAI.

**Delete** is refused while any chunk set embeds with the model, and while it is the
configured default for new corpora; the reason names the sets rather than making you find
out by trying.

Names are compared with `:latest` normalised away — Ollama reports
`nomic-embed-text:latest` and a chunk set records `nomic-embed-text`.

Only embedding models are listed. Ollama serves chat models from the same endpoint and
they cannot embed, so offering them would turn a bad pick into a 503 at index time. The
filter is a name heuristic and is labelled as one; the real check still runs when a model
is chosen.

### Settings

Deployment-wide: default embedding model and chunk settings for NEW corpora, refresh interval,
concurrency limits, upload size caps, Qdrant and Ollama endpoints (read-only, showing what
the environment supplied). A **Check connectivity** button that actually calls both and
reports what it found.

## Live updates

One SSE stream, `GET /api/events`, multiplexing job progress, health changes, and corpus
state. Reconnects with backoff; shows a "reconnecting" indicator rather than quietly
freezing. Events are scoped to the tenant.

Polling fallback if SSE fails twice, at 5 s, with the UI saying it has fallen back.

## Accessibility and polish

Keyboard-first: `/` focuses search, `Ctrl/Cmd+K` opens the corpus switcher, `Esc` closes.
Visible focus rings, labelled controls, dialogs that trap focus and restore it. Empty
states that say what to do next rather than "No data". Errors that quote the server's
message instead of "Something went wrong".

## Not in v1

Bulk operations across corpora; a file browser for indexed content; saved searches; charts
of index growth; a settings page for every option in `appsettings.json`. Each is a
reasonable idea and none of them answers one of the four questions at the top.
